# T06 — الصفحة الرئيسية وقائمة المبادرات وصفحة المبادرة

- **الفرع:** `task/T06-public-site`
- **يعتمد على:** T05
- **المراجع:** `docs/SPEC.md` FR-34..37, §7, §8

## الهدف
الواجهة العامة: عدّادا المبادرات، القائمة بتبويبين، وصفحة المبادرة مع نسخ الحساب.

## المطلوب
1. `App\Support\HijriDate`: عرض تاريخ هجري (أم القرى عبر `IntlDateFormatter` مع `islamic-umalqura`) وميلادي معًا مع اسم اليوم، وتحويل هجري→ميلادي (تقدير ثم فحص ±40 يومًا)، وعدّ تنازلي بالأيام بصياغة عربية صحيحة.
2. الصفحة الرئيسية (جوال وكمبيوتر): **بطاقتان متجاورتان: عدد المبادرات المتاحة وعدد المبادرات المغلقة**، قسم تعريفي، "كيف تشارك"، وأحدث المبادرات (الاسم الأول للمبادر فقط).
3. `/beneficiaries`: تبويبان "المتاحة" و"المغلقة". البطاقة: اسم المستفيد **كاملًا بلا اقتطاع** (يلتف على أسطر)، ونسبة التقدّم، والمواعيد بالتقويمين.
4. `/beneficiaries/{id}`: للمتاحة: اسم المصرف، **اسم صاحب الحساب كما في المصرف**، **رقم الحساب مع زر نسخ**، **الآيبان مع زر نسخ**، بتأكيد "تم النسخ". الأرقام `dir="ltr"` بأرقام لاتينية. للمغلقة: **لا تعرض بيانات الحساب**.
5. SEO: عنوان ووصف وOG لكل صفحة.

## معايير القبول
- [ ] العدّادان صحيحان ويظهران بجانب بعضهما على 360px و1280px.
- [ ] اسم مستفيد طويل جدًا (60 حرفًا) لا يُقتطع ولا يكسر التخطيط.
- [ ] المغلقة لا تكشف أي بيانات بنكية في HTML ولا في استجابات Livewire.
- [ ] أزرار النسخ تعمل ولها بديل عند رفض الحافظة.

## الاختبارات المطلوبة
- اختبار العدّادات، وإخفاء بيانات المغلقة/غير المعتمدة.
- اختبار `HijriDate` بتواريخ معروفة وفي حدود الأشهر (يوم 30 غير موجود).
- فحص أن HTML المغلقة لا يحتوي الآيبان.
